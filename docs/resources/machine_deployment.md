# Machine Deployment (Resource)

A node group of a cluster on the management cluster the provider block names, the way `aws_eks_node_group` is one of an EKS cluster: a `MachineDeployment` (`template`), or one entry of the Cluster's topology workers when the cluster uses a ClusterClass (`class`), owned by this resource's own field manager so `capi_cluster` and other groups never touch it. The API version, the default Kubernetes version, the failure domains and the worker classes come from the live Cluster; the configuration states only what the group is. `replicas` and `autoscaling` are exclusive: with autoscaling the cluster autoscaler owns the count and it never shows as drift. Import with `namespace/cluster/name`.

## Example Usage

```terraform
# Direct mode: the group owns a MachineDeployment built from the template
# resources' refs. Changing a ref rolls the group out.
resource "capi_machine_template" "worker" {
  name           = "worker"
  namespace      = "capi"
  infrastructure = "tinkerbell"
  spec = {
    hardwareAffinity = { required = [{ labelSelector = { matchLabels = { type = "worker" } } }] }
  }
}

resource "capi_bootstrap_template" "worker" {
  name      = "worker"
  namespace = "capi"
  bootstrap = "talos"
  spec = {
    generateType = "worker"
    talosVersion = "v1.13"
  }
}

resource "capi_machine_deployment" "workers" {
  cluster   = capi_cluster.prod.name
  namespace = "capi"
  name      = "workers"
  replicas  = 3
  version   = "v1.34.0"

  template = {
    infrastructure = capi_machine_template.worker.ref
    bootstrap      = capi_bootstrap_template.worker.ref
  }

  labels  = { tier = "worker" }
  rollout = { strategy = "RollingUpdate", max_surge = 1, max_unavailable = 0 }
  deletion = {
    node_drain_timeout    = "10m"
    node_deletion_timeout = "2m"
  }
}

# Topology mode: the group is one entry of the Cluster's topology workers,
# instantiating a worker class of the ClusterClass. The cluster autoscaler
# owns the count between min and max.
resource "capi_machine_deployment" "autoscaled" {
  cluster   = capi_cluster.prod.name
  namespace = "capi"
  name      = "workers-amd64"

  class = {
    name      = "worker-amd64"
    variables = { diskSize = "200Gi" }
  }

  autoscaling = { min = 2, max = 8 }

  scale_to_zero_on_delete = true
}
```

## Schema

### Required

- `cluster` (String) Name of the Cluster.
- `name` (String) Group name: the MachineDeployment's name, or the topology entry's.

### Optional

- `annotations` (Map of String) Annotations on the machines.
- `autoscaling` (Attributes) Let the cluster autoscaler own the count between `min` and `max` (the `cluster.x-k8s.io/cluster-api-autoscaler-node-group-*` annotations). (see [below for nested schema](#nestedatt--autoscaling))
- `class` (Attributes) Topology mode: the ClusterClass worker class the group instantiates, with variable overrides. Exclusive with `template`. (see [below for nested schema](#nestedatt--class))
- `deletion` (Attributes) Node lifecycle timeouts, as Go durations. (see [below for nested schema](#nestedatt--deletion))
- `failure_domain` (String) Failure domain, validated against the Cluster's `status.failureDomains`.
- `labels` (Map of String) Labels on the machines (and their nodes).
- `namespace` (String) Namespace of the Cluster. Default `default`.
- `replicas` (Number) Desired machines. Exclusive with `autoscaling`.
- `rollout` (Attributes) Rollout strategy. (see [below for nested schema](#nestedatt--rollout))
- `scale_to_zero_on_delete` (Boolean) Scale the group to zero and wait for its machines to drain before deleting the object, for providers that release hardware slowly.
- `template` (Attributes) Direct mode: the machine template and bootstrap config template of the group, from `capi_machine_template` and `capi_bootstrap_template` `ref`s. Changing a ref rolls the group out. Exclusive with `class`. (see [below for nested schema](#nestedatt--template))
- `timeouts` (Attributes) (see [below for nested schema](#nestedatt--timeouts))
- `version` (String) Kubernetes version of the machines (`v1.34.0`). Defaults to the cluster's topology version; required without a ClusterClass.
- `wait` (Attributes) What to wait for after the object is applied. Default conditions: Available, MachinesUpToDate. (see [below for nested schema](#nestedatt--wait))

### Read-Only

- `conditions` (Attributes List) The MachineDeployment's conditions. (see [below for nested schema](#nestedatt--conditions))
- `id` (String) The ID of this resource.
- `manifest` (String) What was applied: the MachineDeployment, or the Cluster patch carrying the topology entry.
- `object_name` (String) Name of the realised MachineDeployment (generated by the topology controller in topology mode).
- `status` (Attributes) The MachineDeployment's status. (see [below for nested schema](#nestedatt--status))

## Import

Import is supported using the following syntax:

In Terraform v1.12.0 and later, the [`import` block](https://developer.hashicorp.com/terraform/language/import) can be used with the `identity` attribute, for example:

```terraform
import {
  to = capi_machine_deployment.workers
  identity = {
    namespace = "capi"
    cluster   = "prod"
    name      = "workers"
  }
}
```
