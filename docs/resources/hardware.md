# Hardware (Resource)

One bare-metal machine registered with Tinkerbell on the management cluster the provider block names: a `Hardware`, and with `bmc` a rufio `Machine` and its credentials `Secret` (`<name>-bmc-auth`), which have no life without each other. The Tinkerbell stack (tink, rufio) must serve those kinds. Delete refuses while a TinkerbellMachine owns the Hardware, naming it; `force` powers the machine off through its BMC first. Import with `namespace/name`.

## Example Usage

```terraform
# A control-plane machine: its Tinkerbell Hardware, rufio Machine and BMC
# credentials Secret. A machine template selects it by label.
resource "capi_hardware" "cp_1" {
  name      = "cp-1"
  namespace = "capi"
  cluster   = "prod"

  network = {
    mac_address = "aa:bb:cc:dd:ee:01"
    ip_address  = "10.0.80.11"
    netmask     = "255.255.255.0"
    gateway     = "10.0.80.1"
    nameservers = ["10.0.80.1"]
  }
  disk = { device = "/dev/nvme0n1" }
  bmc = {
    address  = "10.0.80.101:16992" # Intel AMT by port; Redfish otherwise
    username = "admin"
    password = var.bmc_passwords["cp-1"]
  }
  labels = { type = "cp" }
}

# A worker without out-of-band management, booted by hand; force lets destroy
# proceed while a TinkerbellMachine still owns it.
resource "capi_hardware" "worker_1" {
  name      = "worker-1"
  namespace = "capi"
  cluster   = "prod"

  network = { mac_address = "aa:bb:cc:dd:ee:11", ip_address = "10.0.80.21", netmask = "255.255.255.0", gateway = "10.0.80.1" }
  disk    = { device = "/dev/sda" }
  labels  = { type = "worker" }
  force   = true
}
```

## Schema

### Required

- `name` (String) Hostname; the object names.
- `network` (Attributes) The primary interface. (see [below for nested schema](#nestedatt--network))

### Optional

- `adopted` (Boolean) The machine already runs the cluster: mark the Hardware provisioned and keep it off PXE, so CAPT adopts the node rather than re-imaging it.
- `bmc` (Attributes) Out-of-band management. Redfish with basic auth by default; Intel AMT when the port is 16992 or 16993. (see [below for nested schema](#nestedatt--bmc))
- `cluster` (String) Cluster name stamped as the `cluster.x-k8s.io/cluster-name` label.
- `disk` (Attributes) The install disk. (see [below for nested schema](#nestedatt--disk))
- `force` (Boolean) On destroy, power the machine off through its BMC and delete the objects even while a TinkerbellMachine owns the Hardware.
- `labels` (Map of String) Labels on the Hardware, which a machine template's `hardwareAffinity` selects by (`type = "cp"`).
- `namespace` (String) Namespace: the one CAPT looks for Hardware in, the cluster's. Default `default`.
- `timeouts` (Attributes) (see [below for nested schema](#nestedatt--timeouts))

### Read-Only

- `id` (String) The ID of this resource.
- `manifest` (String) The applied objects as YAML, the Secret's credentials redacted.
- `status` (Attributes) What CAPT has done with the Hardware. (see [below for nested schema](#nestedatt--status))

## Import

Import is supported using the following syntax:

In Terraform v1.12.0 and later, the [`import` block](https://developer.hashicorp.com/terraform/language/import) can be used with the `identity` attribute, for example:

```terraform
import {
  to = capi_hardware.cp_1
  identity = {
    namespace = "capi"
    name      = "cp-1"
  }
}
```
