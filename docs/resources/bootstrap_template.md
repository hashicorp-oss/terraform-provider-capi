# Bootstrap Template (Resource)

A bootstrap provider's `<Bootstrap>ConfigTemplate`, the bootstrap half of a worker class or MachineDeployment. CAPI templates are immutable, so this resource works like a launch template: a spec change creates a new object named `<name>-<hash>`, `ref` moves to it, consumers roll out, and older revisions are deleted once nothing references them (a MachineSet keeps the old template during a rollout) beyond `revision_history`. Import with `namespace/object_name`.

## Example Usage

```terraform
# A Talos worker config template.
resource "capi_bootstrap_template" "worker" {
  name      = "worker"
  namespace = "capi"
  bootstrap = "talos"
  spec = {
    generateType = "worker"
    talosVersion = "v1.13"
    configPatches = [
      { op = "add", path = "/machine/install/disk", value = "/dev/sda" },
    ]
  }
}
```

## Schema

### Required

- `bootstrap` (String) Bootstrap provider name as clusterctl knows it (`talos`, `kubeadm`). Selects the kind from the installed CRDs when `kind` is unset.
- `name` (String) Logical name. Each revision is the object `<name>-<hash of the spec>`.
- `spec` (Dynamic) The template's inner spec (`spec.template.spec`), as an object with the CRD's camelCase keys. Any change is a new revision; consumers move their `ref` and CAPI rolls the change out.

### Optional

- `annotations` (Map of String) Annotations on every revision.
- `api_version` (String) `group/version` of the template kind. Resolved from the installed CRDs at apply when unset; name it (from `data.capi_provider_components`) to render completely at plan.
- `kind` (String) Template kind. Resolved from the provider's CRDs at apply when unset.
- `labels` (Map of String) Labels on every revision.
- `namespace` (String) Namespace. Default `default`.
- `revision_history` (Number) How many unreferenced older revisions to keep. Referenced revisions are never deleted. Default `1`.
- `timeouts` (Attributes) (see [below for nested schema](#nestedatt--timeouts))

### Read-Only

- `id` (String) The ID of this resource.
- `object_name` (String) Name of the current revision's object.
- `ref` (Attributes) Reference to the current revision, for `capi_machine_deployment`, `capi_cluster_class` and `capi_cluster`. (see [below for nested schema](#nestedatt--ref))
- `revision` (String) Content hash of the current revision.
- `revisions` (Attributes List) Every revision object still present, newest first by name, and what refers to it. (see [below for nested schema](#nestedatt--revisions))

## Import

Import is supported using the following syntax:

In Terraform v1.12.0 and later, the [`import` block](https://developer.hashicorp.com/terraform/language/import) can be used with the `identity` attribute, for example:

```terraform
# The logical name: the newest revision is imported.
import {
  to = capi_bootstrap_template.worker
  identity = {
    namespace = "capi"
    name      = "worker"
  }
}
```
