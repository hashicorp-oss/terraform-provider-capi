# Provider (Resource)

One CAPI provider on the management cluster the provider block names, driven through the clusterctl lifecycle the way `aws_eks_addon` drives an addon: create is `clusterctl init` (converging: a provider installed at another version is upgraded first), a changed entry is `clusterctl upgrade apply` (a changed customization at the same version re-renders it), destroy is `clusterctl delete` keeping its CRDs. A provider that was already installed when the resource was created, or that is imported, is adopted: the resource manages its version, but destroy leaves it installed for whatever installed it (a warning says so at plan time); the adoption is recorded in private state. The customizations (`deployment`, `manager`, `patches`, ...) follow the cluster-api-operator provider CRDs without needing the operator. Declare the `core` provider explicitly and have the others depend on it; on a cluster's first init clusterctl adds the core itself when missing, and this resource asks it not to add the kubeadm providers. A provider also declared in a `capi_cluster`'s maps is managed twice; keep it in one place. Import with `type/name`.

## Example Usage

```terraform
# The core provider first; the others depend on it so clusterctl never adds
# defaults of its own.
resource "capi_provider" "core" {
  type    = "core"
  name    = "cluster-api"
  version = "v1.14.0"
  manager = {
    feature_gates = { ClusterTopology = true, MachinePool = true }
  }
}

resource "capi_provider" "tinkerbell" {
  type         = "infrastructure"
  name         = "tinkerbell"
  version      = "v0.7.9"
  fetch_config = { owner = "tinkerbell-community" }
  manager      = { feature_gates = { ClusterTopology = true } }

  depends_on = [capi_provider.core]
}

resource "capi_provider" "talos_bootstrap" {
  type         = "bootstrap"
  name         = "talos"
  version      = "v0.8.2"
  fetch_config = { owner = "sidero-community" }

  depends_on = [capi_provider.core]
}

resource "capi_provider" "talos_control_plane" {
  type         = "control-plane"
  name         = "talos"
  version      = "v0.7.1"
  fetch_config = { owner = "sidero-community" }

  depends_on = [capi_provider.core]
}

resource "capi_provider" "helm" {
  type = "addon"
  name = "helm"

  depends_on = [capi_provider.core]
}

# Objects of a provider take its kinds, so they render at plan.
resource "capi_machine_template" "worker" {
  name           = "worker"
  namespace      = "capi"
  infrastructure = capi_provider.tinkerbell.name
  api_version    = capi_provider.tinkerbell.kinds["TinkerbellMachineTemplate"].api_version
  spec           = { hardwareAffinity = { required = [{ labelSelector = { matchLabels = { type = "worker" } } }] } }
}
```

## Schema

### Required

- `name` (String) Provider name as clusterctl knows it (`cluster-api`, `tinkerbell`, `talos`, `helm`).
- `type` (String) Provider type: core, infrastructure, bootstrap, control-plane, ipam, addon.

### Optional

- `additional_manifests` (String) Inline YAML content of additional manifests to apply along with the provider components. Supports multi-document YAML (separated by `---`).
- `config_variables` (Map of String) Template variables injected into the provider's component YAML during processing (`${VAR}` substitution). These take precedence over clusterctl config and environment variables.
- `deployment` (Attributes) Deployment customization for the provider controller. (see [below for nested schema](#nestedatt--deployment))
- `fetch_config` (Attributes) Where provider components are fetched from. Set `owner` (and `repository` for providers clusterctl does not know) to build `https://github.com/{owner}/{repository}/releases/{version}/{type}-components.yaml`; `url` and `oci` are used verbatim and exclude the other attributes. (see [below for nested schema](#nestedatt--fetch_config))
- `manager` (Attributes) Controller manager configuration for the provider. (see [below for nested schema](#nestedatt--manager))
- `manifest_patches` (List of String) JSON merge patches applied to rendered provider manifests. Each entry is an inline YAML/JSON blob string (RFC 7396). Cannot be used together with `patches`.
- `patches` (Attributes List) Strategic merge patches or RFC 6902 JSON patches applied to rendered provider manifests. Cannot be used together with `manifest_patches`. (see [below for nested schema](#nestedatt--patches))
- `secret_config_variables` (Map of String, Sensitive) Sensitive template variables injected into the provider's component YAML. Same mechanism as `config_variables` but for secret values.
- `timeouts` (Attributes) (see [below for nested schema](#nestedatt--timeouts))
- `variables` (Map of String) clusterctl variables for the install (`CLUSTER_TOPOLOGY = "true"`), ahead of the clusterctl config file and the environment.
- `version` (String) Release tag to install (e.g. `v0.7.9`). Omit for clusterctl's latest release.

### Read-Only

- `id` (String) The ID of this resource.
- `installed_version` (String) The version clusterctl's inventory reports.
- `kinds` (Attributes Map) The CRD kinds the provider serves, keyed by kind name, at the API version objects of it should use. (see [below for nested schema](#nestedatt--kinds))
- `namespace` (String) Namespace the provider runs in.
- `ref` (Attributes) Reference for other resources: type, name and installed version. (see [below for nested schema](#nestedatt--ref))

## Import

Import is supported using the following syntax:

In Terraform v1.12.0 and later, the [`import` block](https://developer.hashicorp.com/terraform/language/import) can be used with the `identity` attribute, for example:

```terraform
import {
  to = capi_provider.tinkerbell
  identity = {
    type = "infrastructure"
    name = "tinkerbell"
  }
}
```

<!-- schema generated by tfplugindocs -->
### Identity Schema

#### Required

- `name` (String) Provider name as clusterctl knows it.
- `type` (String) Provider type: core, infrastructure, bootstrap, control-plane, ipam or addon.

The [`terraform import` command](https://developer.hashicorp.com/terraform/cli/commands/import) can be used, for example:

```shell
#!/bin/bash
# type/name as clusterctl's inventory lists the provider.
terraform import capi_provider.tinkerbell infrastructure/tinkerbell
```
